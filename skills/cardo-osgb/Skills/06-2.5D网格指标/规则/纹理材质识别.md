# 纹理/材质识别（P0）

> 适用：模型本身不含绿化/道路语义图层，但 b3dm 带内嵌贴图与 UV。
> 目标：给出**可核对、可交付**的绿化率与道路占比代理值，带区间与置信度；不把“本模型不含该信息”当结论。
> 参数表：`纹理材质参数.json`（算法、阈值、出处、许可边界都以该文件为准）。

## 1. 结论先行

| 项 | 结论 |
|---|---|
| 是否纳入产品能力 | **不纳入**。两轮真值校核均未达阈值（第 2 轮：绿化格级 IoU 0.3914 < 0.70、道路格级 0.4469 < 0.60），**保留为诊断口径**：可出数，但 07/08 按“纹理代理·诊断”标注，不得当正式绿化率/道路占比对外引用。 |
| 首版样例值（v2） | 绿化率 **34.78%**（区间 28.10%–38.96%，置信度 中）；道路占比 **21.32%**（区间 14.84%–28.33%，置信度 中）。均为公园样例的纹理覆盖代理值，不是用地面积。 |
| 定位 | **代理值，不是平面用地面积**；用于量级判断与方案对比，正式用地口径仍需外部绿地/道路矢量复核。 |
| 不做什么 | 不做语义分割、不训练模型、不引入受限许可权重；P1（正射深度学习）不在本版范围。 |

## 2. 算法

1. 遍历 b3dm → GLB，取每个 primitive 的 `POSITION`、`NORMAL`、`TEXCOORD_0` 与材质漫反射贴图；
2. 三角面几何法线 `nz ≥ 0.5` 视为朝上表面；取重心 x/y 与重心 UV；
3. 按 UV `mod 1` 采贴图（解码上限 256 px），得到 RGB 与 HSV；
4. 计算可见光植被指数：
   - `ExG = 2g − r − b`
   - `VARI = (g − r)/(g + r − b + ε)`
   - `GLI = (2g − r − b)/(2g + r + b + ε)`
5. 绿 = `ExG ≥ 阈值` 且 `H∈[40,130]`（Pillow 0–255）、`S≥50`、`V≥30`；
   ExG 阈值由 **Otsu** 自动确定（clamp `[0.03,0.15]`，样本不足回退 `0.05`）；
6. 道路 = 非绿 且 `S<40`、`V∈[35,215]`、`ExG<0.35×阈值`、离地 `≤0.35 m`、且不在 2.5D 建筑掩膜内；
7. 按 1.0 m 网格聚合；绿化率/道路占比 = 对应样本数 / **模型覆盖范围内全部朝上表面纹理样本**（含建筑屋面）；
8. 区间 = 网格 `0.5/1.0/2.0 m` × ExG 阈值三档（道路再加饱和三档 × 高度三档）的 min–max；
9. 置信度：纹理观测格占 bbox 网格 ≥60% 且每格样本中位 ≥8 → `medium`，否则 `low`。

### 2.1 分母口径（写死）

- **绿化率分母 = 模型覆盖范围内全部朝上表面纹理样本（含建筑屋面，按样本数加权）**；
- **道路占比分母相同**，分子只计非建筑掩膜、近地面的样本；
- 空洞/无纹理面按无观测处理，不计入；
- 不采用“扣掉屋顶”的分母，避免与片区用地面积口径对不上。

### 2.2 建筑掩膜的作用

- 道路分子：排除建筑屋面/立面，避免把灰色屋顶算成道路；
- 诊断：给出 `nonRoofGreenShare`（非屋面口径绿化占比）仅作对照，不作为主指标；
- **绿化率分母不扣屋面**；绿色屋面/绿色围挡会按绿色样本保留，这是已知误判源。

## 4. 许可边界

**只用许可干净的算法与组件**：ExG/VARI/GLI（公开方法）、Otsu（公开方法）、Pillow HSV 阈值（自研规则）、
UV 采样（自研实现）、2.5D 建筑掩膜（包内几何方法）；运行依赖 numpy（BSD-3-Clause）、Pillow（HPND）。

**不进入交付链路**：RandLA-Net（CC BY-NC-SA 4.0，禁商用）、SegFormer 官方权重（NVIDIA 非商用）、
LoveDA / OpenEarthMap（CC BY-NC-SA 4.0）、OpenDroneMap（AGPL-3.0）。后续若引入 P1 正射深度学习，
必须在包内单独标记许可、权重来源与商用限制，不得静默混入。

## 5. 与 05 纹理诊断的关系

- 05 `纹理按格颜色诊断.json` 仍是 **diagnostic-only**，不进入 7 条指标；
- 06 的 P0 复用同一套 UV 采样思路，但增加了植被指数、Otsu 阈值、建筑掩膜、区间与置信度；
- 05 的 `greenShare`（样本加权 11.42%、按格中位 7.01%）可作为采样正确性的旁证，不作为精度依据。

## 6. 真值校核（P0）

> 状态：**已完成，未达标**。用某公园样例的一个 50 m × 50 m 混合块（草地 + 硬质广场 + 水体 + 林地边缘）
> 人工勾绘真值（`cardo/texture-truth/v1`），绿化 IoU 目标 ≥0.70、道路 ≥0.60，实测均未达到。

### 6.1 方法

1. 用 `validate_texture_truth.py` 生成 1 m 正射影像（每格平均 RGB）与逐格 `greenShare/roadShare`；
2. 在正射影像上人工勾绘 1 个片区（`cardo/texture-truth/v1`，矩形/多边形），道路优先于绿化；
3. 预测掩膜：`greenShare ≥ 0.5` / `roadShare ≥ 0.5`；
4. IoU = TP / (TP + FP + FN)，同时给格级与像素级两种（第 1 轮像素级为样本加权，第 2 轮起为三角面面积加权）；
5. 不调阈值凑数；达不到就记录原因与后续条件。

### 6.2 两轮结果并排（同一 50×50 m 真值，阈值 0.70/0.60 未动）

| 类别 | 口径 | 第 1 轮 IoU | 第 2 轮 IoU | 变化 | 阈值 | 结论 |
|---|---|---|---|---|---|---|
| 绿化 | 格级 | 0.3850 | **0.3914** | +0.0064 | ≥0.70 | 未达标 |
| 绿化 | 像素级 | 0.4450 | **0.3935** | −0.0515 | ≥0.70 | 未达标 |
| 道路 | 格级 | 0.4282 | **0.4469** | +0.0187 | ≥0.60 | 未达标 |
| 道路 | 像素级 | 0.2767 | **0.4115** | +0.1348 | ≥0.60 | 未达标 |

第 2 轮精确率 / 召回率：

| 类别 | 格级 P / R | 像素级 P / R |
|---|---|---|
| 绿化 | 0.7050 / 0.4681 | 0.7233 / 0.4632 |
| 道路 | 0.5432 / 0.7160 | 0.5263 / 0.6536 |

> 第 1 轮像素级为样本加权；第 2 轮改为三角面面积加权，像素级数字与第 1 轮不是同一权重口径，
> 格级 IoU 才是可并排比较的主口径。

### 6.3 第 2 轮做了什么（只动三处）

1. **树冠明度分层**：新增亮部低饱和冠芯分支（`S≥10, V≥40, H40–95, ExG≥0.5×阈值`），与暗部分支并联；
2. **格级多数票补洞**：非绿格若 8 邻域中 ≥5 个是绿，按 0.5 下限软填充（只补内部空洞，不向外扩张）；
3. **道路放宽高差**：`离地 ≤0.35 m` → `≤0.8 m`，敏感性 `0.45/0.8/1.3 m`；建筑掩膜仍整体排除屋面；
4. **混合像元面积加权**：格内按三角面 3D 面积加权，替代数面片；区间按新权重重算。

### 6.4 未达标原因（两轮合并，如实记录）

1. **绿化格级几乎没动（+0.0064）**：冠芯补判把一部分灰绿铺装/水体也算进来，精确率略降；
   补洞只覆盖 303 格，救不回成片漏判；召回率仍只有 0.47。
2. **绿化像素级反而降了 0.0515**：这不是分类变差，而是面积加权后大三角面（广场/屋面）权重上升，
   绿化真值的像素权重被稀释；说明像素级对权重口径敏感，不能单独拿来下结论。
3. **道路召回上来了（格级 R 0.67→0.72），精确率仍 0.54**：放宽高差确实救回坡道/林间步道，
   但灰色铺装、屋面边缘、阴影也被一并算进道路。
4. **根因未变**：1 m 格混合像元、水体青蓝边缘、树冠阴影/高光、贴图分辨率与 UV 拉伸；
   这些不是调三个参数能解决的。
5. **公园样例不代表街区**：两轮都只在一个公园类片区上校核，绿化连片、广场规整；老旧街区会更差。
6. **人工真值本身是保守勾绘**：水体、建筑、阴影不标，边界按正射影像目视，存在 ±1 格误差。

### 6.5 后续条件（按用户要求，不做第三轮）

1. 逐项目人工真值或外部绿地/道路矢量复核（IND-GAP-009）；
2. 引入许可干净的语义分割（P1，需单独标记权重来源与商用限制）后重做真值校核；
3. 若继续像元法：需要 1 m 以下网格 + 面内多样本 + 水体/铺装独立类，并先在街区类片区建真值；
4. 达到绿化 IoU ≥0.70、道路 IoU ≥0.60 才谈纳入产品能力。

### 6.6 给用户看的一句话

- **能干什么**：在公园/开敞绿地这类绿化连片、道路规整的模型上，给出带区间和置信度的
  绿化率/道路占比**量级参考**（样例 34.78% / 21.32%）。
- **不能干什么**：不能当正式用地面积；不能用于老旧街区碎片化绿化、窄巷道路、阴影反光路面的报数；
  不能对外宣称精度达标。
- **什么条件下才谈纳入**：有逐项目真值或外部用地矢量复核，且绿化 IoU ≥0.70、道路 IoU ≥0.60。

### 6.7 这个 IoU 能代表什么、不能代表什么

- **能代表**：在同类**公园/开敞绿地**场景（绿化连片、道路规整、贴图清晰、无大面积遮挡）下，
  该像元级方法能把大块草地/树冠与硬质路面分开到“量级参考”水平（格级 IoU 0.39/0.45），**不足以当正式面积**；
- **不能代表**：老旧街区的碎片化绿化（花坛、行道树、屋顶绿化、垂直绿化）、窄巷道路（宽度接近或小于 1 m 网格）、
  阴影/反光路面、铺装与屋顶同色、贴图拉伸严重的模型；
- **保守表述**：街区类项目默认按 `low` 置信度使用，必须带区间，并优先用外部绿地/道路矢量复核；
  不得用公园样例的 IoU 对外宣称“通用可用”。

## 7. 已知局限

1. 纹理覆盖代理，非平面用地面积；分母含建筑屋面；
2. 绿色屋面/绿色围挡/阴影下的草地/树冠遮挡/贴图拉伸会误判；
3. 道路要求近地面、低饱和灰度，窄巷/反光路面/彩色铺装会漏判；
4. Otsu 阈值是场景自适应，同一项目不同片区阈值可能不同；阈值已写入 `现状指标.json.params.texture`；
5. 置信度只分 `low/medium`，P0 不声称 `high`；
6. 仅有样例片区真值校核，未逐项目校核（IND-GAP-009）。
