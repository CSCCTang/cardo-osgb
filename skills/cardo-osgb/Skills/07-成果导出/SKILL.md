# 07 · 成果导出

> 把过程 JSON 变成人读成果：**三项成果各出「成品版 + 溯源版」，必要时加一份依据对照表**。
> 成品版与内部件**分目录存放**（`成果文件/成品版/`、`成果文件/内部件/`）。
> **不新增任何数值**：每个数字都能在 `体检.json` / `现状指标.json` 找到同源。

## 何时用

- 06 通过之后；
- 改了文档样式但不想重跑全链：`--from 07`。

## 执行命令（工作区根）

```bash
python Skills/07-成果导出/scripts/export_deliverables.py
python Skills/07-成果导出/scripts/export_deliverables.py --out 成果文件
```

## 输入 / 输出

| 输入 | 输出（默认 `成果文件/`，成品版与内部件分存、一成果一目录） |
|---|---|
| `转换产物/cardo-lowair-model.json` | `成品版/模型体检报告/模型体检报告_成品版.docx`（概要 / 工具链 / 结构 / 配准 / 判据 / 结论）；`内部件/模型体检报告/模型体检报告_溯源版.docx`（另加工具链备注、边界与说明、未验证项） |
| `过程文件/05-模型体检/体检.json` | `成品版/现状指标/现状指标_成品版.xlsx`（导览 / 指标 / 场地要素明细 / 敏感性 / 范围参数 / 术语）；`内部件/现状指标/现状指标_溯源版.xlsx`（另加可观测类型 / 技术口径 / 边界与说明 / 诊断 / 算法溯源） |
| `过程文件/06-2.5D网格指标/现状指标.json` | `成品版/指标说明/指标说明_成品版.docx`（第 0 章导读 + 逐条指标 + 术语表）；`内部件/指标说明/指标说明_溯源版.docx`（另加溯源行、口径原文、局限原文、缺口编号、逐条证据） |
| 同上 | `内部件/现状指标/现状指标依据对照表.xlsx`：**指标依据 / 逐数明细 / 未通过**（三 sheet），每个数 → 输入图层 / 算法 / 参数 / 区间 / 局限 / 自检（`scripts/build_evidence_xlsx.py`） |
| — | `过程文件/07-成果导出/导出日志.json`：运行结论（status / stage / exitCode / problems）+ 七件成果的**落盘清单 / 字节数 / sha256** + 输入源指纹 |

**两份主文件分工**（《Cardo四包通用规范》第 2 节）：成品版是交付业主的定稿，正文干净，
无溯源标注、缺口提示、内部备注、判断过程，读起来就是正式成稿；溯源版给内部复核与审计，
保留口径原文、局限原文、字段级证据与缺口编号。两份**同一次运行、同一份 JSON**产出，
导出后自校验「指标行数与每个可读值 / 区间 / 置信度完全一致」——不许人工删改另存。
成品版不收录 C 级内部诊断指标（如纹理代理的绿化率、道路占比），也不放可观测类型矩阵。

**导出日志**是这一步的留痕（之前 product 是 None，过程文件里没有 07 目录）：
有了它，「成果 ↔ 输入 ↔ 一次运行」三者可对账——交付出去的成果能立刻说清是哪次跑的、
基于哪个模型包、哈希是多少。**成功与失败都写**：失败时写明卡在哪一步、退出码、原因、
以及当时已落盘的文件与哈希——否则日志停在上一次成功的那版，事后对账会认错版本。

## 可读性分层（本版新增）

成果是给人看的，而 `现状指标.json` 是给机器看的——**JSON 的口径一个字不改**，
「怎么讲给人听」全部集中在 `scripts/readability.py`（术语词典、59 条指标的白话说明、
可用等级 A/B/C、单位与置信度中文化、可读值格式化）。导出脚本只做编排。

三层结构：

| 层 | 位置 | 内容 |
|---|---|---|
| 人读 | xlsx「导览」「指标」、docx 第 0 章 | 可读值（`36.2%` 而不是 `0.361822`）、白话「这个数在说什么 / 怎么用」、可用等级 |
| 审计 | xlsx「技术口径」 | 原始口径全文、局限全文、证据链，一字不改 |
| 机器 | `过程文件/**/*.json` | 数值唯一来源，不受呈现层影响 |

**关键设计**：同一件事的两个口径（栋数 18 / 13、高度 P50 9.9 / 9.2）必须并列出现，
并明确写「对外该用哪个」——这是最容易被误用的一处，藏在附注里等于没说。

## 闸门（回读核对，不过 → exit 3）

1. **xlsx 数值**：逐条指标原始值与 JSON 差 ≤ `1e-9`；**可读值必须能由原始值推出来**
   （`R.readable_value` 重算比对，防"人读层写了个不一样的数"）；置信度显示文本一致。成品版按表头取列核对。
2. **技术口径表**：口径/局限原文必须与 JSON 逐字一致（审计依据，不许改写）。
3. **docx 可检索**：体检报告含模型名、b3dm 数、三角面数、垂直修正量、SRS、exe sha256；
   指标说明含每条指标的**可读值**（溯源版另有「原始 …」括注）。
4. **两份同源**：成品版与溯源版的指标行数（成品版剔除 C 级）、顺序、可读值、区间、置信度必须逐条相等。
5. **成品版词表闸门**：扫成品版全文（段落 + 表格单元格 + xlsx 单元格），
   命中 `待补 / 暂缺 / 缺项 / 未提供 / 资料缺失 / 未配置 / skipped / TODO / 占位 /
   见过程文件 / 过程文件/ / 原始 + 数字 / quality. / 未验证 / 本模型不含 / 需接入` 即 exit 3。
6. **先删旧**：每次导出前删掉上一版同名文件（失败不留"上次的成果"）。
7. **空白页自检**（`scripts/blank_page_guard.py`）：七件成果全部过检；「0 字符 0 图」的页即空白页 → exit 3；同时卡**字号底线 7pt**。

### 空白页自检：两档，不依赖 Office

渲染级检查要 Word/Excel 的 COM，客户机器上不一定有 Office——**不该被要求装 WPS**。
所以自检分两档，自动降级：

| 档位 | 触发条件 | 查什么 |
|---|---|---|
| **渲染级** | 本机注册了 `Word.Application` / `Excel.Application` | docx/xlsx → PDF → 逐页数字符/图片/字号；空白页、页数上限、字号底线三项全实测 |
| **结构级** | 没装 Office（或渲染失败） | 直接读文件结构：docx 走 `word/document.xml`、xlsx 读单元格样式 |

结构级**照旧卡**的两件事：

- **空白页的结构性前兆**——空段落自带显式分页符、空段落设了 `pageBreakBefore`。
  这两种正是当年《指标说明》多出一整张白纸的成因（章末「空段落 + 显式分页符」
  被正文顶到页尾，空段落自己翻一页，分页符又翻一页），命中即拦。
- **字号底线 7pt**——docx 自己走样式继承链（显式 run 字号 → 字符样式 → 段落样式 →
  `basedOn` 链 → `docDefaults`），xlsx 读 `cell.font.size`，与渲染级读出的数值一致。

结构级**做不了**的两件事：页数上限、逐页字符/图片统计——它们必须真的排版一遍才知道。
报告里如实标「未执行」，**不拿「查不到」冒充「查过了没问题」**。

关键口径：**渲染不了 ≠ 有空白页**。旧版把两者混成一个 problem 直接 exit 3，
于是「没装 Office」被当成「成果有毛病」，07 步一挂就卡住 08~16 全链。
现在渲染失败只降级不阻断，只有真查出问题才拦。

自检档位写进 `过程文件/07-成果导出/导出日志.json` 的 `blankPageAudit` 字段，
事后能说清这批成果是「渲染级逐页验过」还是「只做了结构级检查」。

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 七件写出且回读一致、两份同源、成品版词表闸门通过 |
| 2 | 缺输入 / schema 不符 |
| 3 | 写盘失败 / 回读不一致 / 空白页或字号真有问题 |

## 边界

- `成果文件/` **只**放 Office（`.xlsx .docx .pdf`）；JSON/MD/b3dm 一律留在 `过程文件/`。
- 文本口径照搬 JSON：区间写「方法敏感性区间」，不写"误差"；数值不带虚假精度（用 JSON 里的位数）。
- **呈现层不许造数**：`readability.py` 只能做格式化（加百分号、千分位、中文化），
  绝不能重算指标；白话描述只解释既有数字，不引入新数字。
- 图表暂不生成（v1 只出表）；需要时用 `现状指标.xlsx` 的「敏感性」sheet 自行画。

## 调优点

- 想改白话措辞：改 `scripts/readability.py` 的 `PLAIN`（每条指标一句「在说什么」+
  一句「怎么用」）或 `TERMS`（术语表）；**不要**改数字来源；
- 想调整某条指标的可用等级：改 `readability.py` 的 `LEVELS`（A/B/C + 判级理由）；
- 新增指标后忘了登记白话：会退化成"（本版未给白话说明）"——补 `PLAIN` 即可，
  闸门不会因此失败（可读性不是数值正确性）；
- 回读失败最常见原因是浮点格式（`0.366464` 写成 `0.3665`）——用脚本内的 `fmt()` 统一格式。
