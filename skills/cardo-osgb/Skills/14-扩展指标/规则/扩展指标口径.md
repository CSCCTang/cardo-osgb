# 扩展指标口径（extended-indicators-v1）

> 契约：`cardo/lowair-extended-indicators/v1`　　上游：`09–13` 各步的 `summary`
> 本步**不做几何计算**，只把上游已算出的量映射成指标并标注口径与局限。

## 0. 通用处理

1. 读 `SRC` 表里 10 个上游 JSON；文件不存在或读失败 → 该组指标 `value=null` + gap；
2. 对每个指标定义（`DEFS`），按 `summary.<field>` 取值，**不做二次算术**；
3. 区间：只有上游自己给出 `xxxRange` 的指标才带区间，其余 `range=null`；
4. 溯源：每条带 `algoId` / `step` / `evidence`（`相对路径 · summary.字段名`）。

## 1. 与 06 步指标的关系

| | 06 步 | 14 步 |
|---|---|---|
| 契约 | `cardo/lowair-indicators/v1` | `cardo/lowair-extended-indicators/v1` |
| 条数 | 7 条（固定） | 40 条 |
| 口径 | 2.5D 网格法 | 逐条对应上游算法（实例化/分类/分割/矢量化…） |
| 来源 | 03 步的 b3dm（自己算） | 09–13 步的 summary（搬运） |
| 用途 | 规划口径核心指标 | 反映**已落地算法算出了什么** |

**两者并存于同一份成果**：《现状指标.xlsx》有「指标」「扩展指标」两张 sheet，
《指标说明.docx》有第 1 节（核心指标）与第 5 节（扩展指标）。

## 2. 关键口径差异（不要混比）

| 指标 | 06 步 | 14 步 | 为什么不同 |
|---|---|---|---|
| 建筑栋数 | 18（2.5D 网格 4 邻域连通块 + 1 格闭运算） | 13（nDSM 阈值 + 形态学 + 分水岭实例化） | 两套独立算法，网格连通块会把相邻建筑并联，分水岭会把裙房切开 |
| 建筑高度 P50 | 格级 P50（每个 1 m 格的「格高 − 地面」） | 栋间 P50（先算每栋 P50，再对各栋取中位） | 统计单元不同：格 vs 栋 |
| 建筑基底面积 | 无此指标 | 3200 m²（各栋格数 × 1 m²） | 只有实例化路线有栋级面积 |
| 「绿」相关 | `greenery_ratio` = null（无语义） | `vegetation_share` = 0.1678（几何植被） | 几何只能看树冠，不是用地绿化率 |

## 3. 每条指标必须带的东西

| 键 | 含义 |
|---|---|
| `method` | 这个数**怎么算出来的**（人话，含上游口径关键词） |
| `limits` | 已知偏差与不适用场景 |
| `confidence` | high / medium / low |
| `algoId` | 对应 `算法注册表.json` 里的哪条算法（可 `algos` 查） |
| `step` | 产自哪一步（09–14） |
| `evidence` | 哪个文件的哪个字段（可回溯） |

## 4. gaps

| code | 什么时候出 |
|---|---|
| `EXT-GAP-001` | 某条指标上游没这个字段 → 该指标 null + placeholder |
| `EXT-GAP-002` | 整组上游没跑 → 该组指标全 null，记一条汇总 gap |

## 5. 禁则

1. **不把扩展指标说成精度**：所有数值仍带置信度与局限，无真值校核；
2. **不跨口径比较**（见 §2）；
3. **不因为"看起来不一致"就去改上游**——两个算法口径不同，差异是信息不是 bug；
4. **不补造上游没有的量**（如从树冠面积推算绿化率）。
