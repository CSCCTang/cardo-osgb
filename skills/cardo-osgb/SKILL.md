# CardoOSGB · 低空解析流水线

一个文件夹就是这条流水线：独立使用时把 `CardoOSGB/` 整个放进用户的项目文件夹；插件方式下它已装在技能目录里，**不用安装、不用配置**。

**独立工作区、独立交付**：一个包一个工作区、一份交付；四包放同一目录不会自动串联，也不共用状态文件。
跨包只靠产物交接——把本包 `过程文件/06-2.5D网格指标/现状指标.json` 复制给下游 `输入文件/`；xlsx 仅人读留档。
低空产物在下游的定位是**量化证据**（指标表、附图、问题清单），不承担正文叙事。
判断 vs 实测的分工与单会话自足要求，见《Cardo 四包通用规范》（`交付规范/Cardo四包通用规范.md`）。

**交互节奏（默认一口气做到成果）**：
- **默认不停**：进场先跑 `python "<技能目录>/scripts/cardo.py"` 建目录并逐条说明放什么；有料就直接往下做到成果，不逐项请示。
- **只在这三类点停**：① 缺料或输入不合格（说清缺什么、放哪里、怎么补）；② 不可逆或越界操作（删改源文件、写包外目录、覆盖旧成果）；③ 必须由人做的业务取舍（选方案、定口径、改关键参数）。
- **同一轮的多处疑问合并成一次问完**：列成一张清单请用户一次拍板，不要一问一停。
- 只有完全没料时才停；材料到位后直接继续，不需要用户回「继续」。

**放料清单**：`开工.py` 会在工作区生成 `放料清单.md`，列出要什么、放哪、现在到没到；本文档是执行细则。
**首次运行自动备依赖**：缺依赖就在用户缓存（`%LOCALAPPDATA%\cardo\venv-osgb`）按 `requirements.txt`
建虚拟环境并安装（阿里云→清华→USTC→官方源回退），之后复用；技能包目录保持只读。
需本机已装 Python 3.9+。

**不要求装 Office 或 WPS**：全链只依赖包内 Python。07 步有一道「空白页自检」，
装了 Office 就做渲染级（渲成 PDF 逐页数空白），没装就自动降级为结构级
（直接读 docx/xlsx 内部结构判空白页前兆，字号底线照旧卡）——**降级只影响保证强度，
不阻断流程**，自检档位写进 `过程文件/07-成果导出/导出日志.json` 可查。

**包完整性自带校验**：`PACKAGE_MANIFEST.json` 记着关键脚本 / 自带工具二进制 / runtime 依赖的 sha256。
每次开工前先核对一遍，**缺什么、被改过什么，一屏列全**（不用跑到一半才炸）。
拷包时若这个文件没跟过去，用 `python "<技能目录>/Skills/00-Cardo低空解析总控/scripts/package_manifest.py" generate` 重建基线。

**技能包只读**：本文件夹里的 `SKILL.md`、`开工.py`、`requirements.txt`、`Skills/`（含 `tools/` 工具）、`assets/` 在开工过程中一个字节都不会被写；
运行期状态只写工作区与用户缓存。
工作区默认取**当前目录**（插件方式；独立使用时是本文件夹的上一级目录，如 `XX项目/`）：`输入文件/` 放料、`过程文件/` 留痕、`成果文件/` 出活，
`工作区参数.json` 和 `.cardo/`（虚拟环境）也在那里。换项目时把技能文件夹整体拷走即可，不会带走任何项目数据。

在项目文件夹里执行命令（`--workspace` 可显式指定别的工作区）：

```powershell

```

## 先看放料清单

首次运行 `开工.py` 会在工作区根目录生成 **`放料清单.md`**：按项列出「要什么 / 放哪儿（绝对路径）/ 怎么命名 / 是否必需 / 现在到没到」，
每次运行都会刷新。想一项一项确认，就跑：

```text
python "<技能目录>/scripts/cardo.py" --intake
```

它会一项一项问（回车=已放好，s=暂时没有，q=退出），并在你确认后**立即复扫**，没真的放进去不会放行；必需项缺失则停在这一步。

**如果模型包还在拷贝（几个 GB 要几分钟），加 `--wait` 让它等你**：

```text
python "<技能目录>/scripts/cardo.py" --wait 600
```

每 5 秒复扫一次 `输入文件/01-模型包/`，一放进去就自动继续校验与开工，不用你再敲一遍命令。

## 缺料时 AI 该做什么（重要）

缺料**不是错误，是流程的第一步**。命令返回 exit 3 时，按下面做，**不要**替用户编一个包、也**不要**跳过：

1. **读清单**：看终端打印的「放料目录（绝对路径）」，以及 `过程文件/00-总控/待补料.json`
   （里面有「缺什么 / 放到哪 / 怎么准备 / 补齐后重跑」四项，机器可读）。
2. **问用户**（一次只问一项）：把绝对路径和「怎么准备」原样转述给用户，例如
   「请把 OSGB 模型包 zip 放到 `C:\path\to\workspace\输入文件\01-模型包\`。整个 OSGB 目录打成 zip，
   解压后只有一个根目录且含 metadata.xml，坐标系 EPSG:4544。」
3. **等用户放好**（见上文「交互节奏」）：用户放完后重跑 `python "<技能目录>/scripts/cardo.py"`（或用 `--wait 600` 让它自己等）。
4. **用户说没有**：这就是硬缺料。模型包**不能联网补、不能替代、不能伪造**
   —— 记为缺口，停下并说明「缺 OSGB 模型包，无法出成果」，不要拿别的模型顶替。

终端已经替你问好了所有细节，你只要**转述给用户并等他放好**，不要自己造料。

## 开工三步

1. **收料**（只有一项，但要问清）：把 **一个** OSGB 模型包 `.zip` 放进 `输入文件/01-模型包/`。
   要求：标准 Smart3D 布局（包内单一根目录 + `metadata.xml`）；坐标系只收 **EPSG:4544**
   （`4544+垂直码` 会归一为单码，垂直位移由第 04 步补偿）。问清来源（哪个项目、哪次航测、导出参数）。
2. **开工**：

```powershell
python "<技能目录>/scripts/cardo.py" --to 02      # 冒烟：只解包与工具探测，不转换
python "<技能目录>/scripts/cardo.py"              # 全链 01→16（反演 + 场地要素 + 扩展指标 + 能力边界表）
python "<技能目录>/scripts/cardo.py" --check      # 只校验模型包与结构，不跑流水线
```

`开工.py` 每次运行都会：依赖自检（8 个包，首次较慢；缺就建 `.cardo/venv-osgb`，按 阿里云 → 清华 → USTC → 官方源 回退安装）
→ 建目录 → 核对自带工具 → 校验模型包（唯一 zip / 有 metadata.xml / SRS 合规）→ 调 01→14。

3. **按退出码走**。03 调 `3dtile.exe` 转换，耗时取决于模型规模；期间不要重复触发第二条命令。

## 输入

| 项 | 必需 | 放哪 | 要求 |
|---|---|---|---|
| OSGB 模型包 `.zip` | **是** | `输入文件/01-模型包/` | **只放一个**（子目录里放也算）；单一根目录 + `metadata.xml`；SRS 只收 EPSG:4544 |

SRS 不合规时**不要硬跑**：告诉用户当前 SRS 是什么、本链只收 EPSG:4544，需先在建模软件重投影/重导出再打包；没有合规模型就停在这一步，不替代、不伪造。
多个 zip 时请用户移走多余的，只留本次要解析的那个。缺 `metadata.xml`、不是单根目录、缺根瓦片，说明不是标准 Smart3D 布局，请重新导出。

**预检与实跑同一口径**：预检直接调用 01 步的只读体检（`unpack_model.py --check-only`），
判据代码与实跑完全同源——所以「预检说通过」就等于「实跑不会因布局/坐标系被拦」，
不会出现"预检过了、一跑就挂"。预检拦下时给的建议就是可执行的改法，照着改完重新打包即可。

**模型包不能联网补**：它是本项目实测数据，检索不到也不得用别的模型、示例数据或估算指标顶替；缺就停在这一步。

## 成果与验收

- `成果文件/`（成品与内部件分存，一项成果一个目录）：
  - `成品版/模型体检报告/模型体检报告_成品版.docx`
  - `成品版/现状指标/现状指标_成品版.xlsx`
  - `成品版/指标说明/指标说明_成品版.docx`
  - `内部件/模型体检报告/模型体检报告_溯源版.docx`
  - `内部件/现状指标/现状指标_溯源版.xlsx` + `现状指标依据对照表.xlsx`
  - `内部件/指标说明/指标说明_溯源版.docx`
  - **成品版**是交付业主的定稿，正文干净：无溯源标注、缺口提示、内部备注、判断过程；
    **溯源版**给内部复核与审计，保留口径/局限原文、字段级证据与缺口编号。
    两份同一次运行产出，数值逐条一致；成品版另过一道词表闸门（命中缺口用语即 exit 3）。
- 《现状指标依据对照表.xlsx》是**逐数对账**用（内部件）：每条指标 → 输入图层 / 算法 / 参数 / 区间 / 局限 /
  自检结果；口径缺失、区间不包主值、`source` 回指不到文件，07 直接 exit 3（不许出"来路不明"的数）。
- 指标是**估算值 + 方法敏感性区间**，必须连区间一起讲，不能只报单点。
- 《现状指标.xlsx》按「人读 → 审计」分两层：成品版 6 张 sheet（导览 / 指标 / 场地要素明细 /
  敏感性 / 范围参数 / 术语），溯源版另加 5 张内部 sheet（可观测类型 / 技术口径 / 边界与说明 / 诊断 / 算法溯源，共 11 张）：
  - **「导览」**（打开默认停这）：这个片区最实在的几个数、同一指标的两套口径该用哪个、
    可用等级 A/B 怎么读、这份文件怎么翻。
  - **「指标」**（人读层）：可读值（`36.2%` 而不是 `0.361822`）+ 白话说明
    「这个数在说什么 / 怎么用」+ 可用等级 + 置信度中文化。
  - **「技术口径」**（审计层，仅溯源版）：原始口径全文、局限全文、证据链，一字不改，可回溯到算法与源文件。
  - **「场地要素明细」**：几何代理量的逐条位置清单（原先混在指标表里，把表撑得没法看）。
  - 其余辅助 sheet：**敏感性 / 范围参数 / 边界与说明 / 诊断 / 算法溯源 / 可观测类型 / 术语**。
- 《指标说明.docx》**第 0 章「导读」**是关键指标概览与口径对照；
  1.1 节是全量指标总表（一眼看全），1.2 节是核心指标逐条说明，
  之后依次是扩展指标、场地要素明细、术语表（章号随内容动态，成品版不含可观测类型矩阵）。
- 证据：`过程文件/00-总控/运行报告.md`（每步退出码与耗时）、`过程文件/08-验证与成稿/验证报告.json`。
